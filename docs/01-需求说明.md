## 1. 项目背景与目标

用户有大量音游结算图（移动端截图 + 街机实拍照片），希望用本机工具自动识别「游戏 + 歌名 + 难度」，把图片移动整理到「sorted/游戏/歌名」目录，并能按游戏和歌名搜索查看。图片内容始终保留不动。

## 2. 范围

- 支持游戏：舞萌、中二节奏、Arcaea；架构预留后续扩展。
- 识别字段：游戏、歌名、难度名称（如 MASTER / EXPERT / FUTURE）。不识别分数、评级、准确率等。
- 平台：先做 Windows 桌面版，打包成可执行程序分发给他人；架构上不排除未来 Android / iOS。
- 输入：混合存放的多款游戏结算图；结算界面完整可见。

## 3. 功能需求

### 3.1 导入

软件根目录下的 input 文件夹为默认输入，启动时自动扫描并可在运行中点击「刷新」重新扫描，支持常见图片格式（jpg/png 等）。导入后显示进度与统计。
此外支持把图片文件（或包含图片的文件夹）从资源管理器**直接拖入导入页列表**：程序会把其中的图片复制进 input/ 并刷新列表；同名同大小的重复项自动跳过。导入页「文件名」列宽适度（可拖拽调整），「大小」列按内容自适应以保证完整显示。
输入来源不限于手机直拍原图：图片可能经微信等渠道传输而被压缩（分辨率下降、画质重压缩），游戏 UI 也会随版本更新而变化，识别需能容忍这些差异。

### 3.2 游戏识别

软件自动判断每张图属于哪款游戏，无需用户按游戏预先分文件夹。

### 3.3 字段识别

按各游戏配置的结算画面区域，对实拍照片做透视校正与裁剪后，OCR 出歌名和难度名称。
Arcaea 歌名区域可能被右侧角色立绘遮挡，识别不到歌名时归为暂存（待处理），不强行识别。
Arcaea 既有平板截图（约 2360x1640）也有手机横屏截图（约 2400x1080），两者元素位置不同：程序按宽高比自动选用对应的歌名/难度选区。
歌名选区只取歌名行本身，不把其下的曲师名（如 Cosmograph、cubesato）纳入，避免污染识别文本与自学习别名。
歌名 OCR 采用「中文模型为主 + 日文模型补充」：中文模型未自动确认时，用日文识别模型对歌名区域再识别一轮，
覆盖彩色/描边艺术字日文标题（如「モア！ジャンプ！モア！」「だんだん快くなる」类）。

### 3.4 曲库匹配与联网校对

本地曲库优先做模糊匹配。曲库通过指定来源定期/手动联网刷新，识别时不实时联网。Arcaea 用 Arcaea 中文维基；舞萌、中二以官网或 wiki 为主。来源不可用时，停下反馈用户，由用户定方案。无网时降级为仅本地匹配，识别不准的进入校对弹窗或待整理。

### 3.5 校对弹窗

识别不确定时弹窗确认，提供四个选项：

- 手动输入歌名和难度
- 跳过这张
- 标记为待处理
- 暂时跳过，以后添加

手动输入歌名时，弹窗给出若干最相近的曲库歌名候选，可直接点选，减少打字。

### 3.6 整理入库

确认后的图片移动到「sorted/游戏/歌名/」；无法识别的留在「input/」待处理；索引写入本地 SQLite。

### 3.7 查询浏览

按游戏筛选 + 歌名/备注模糊搜索，可叠加难度筛选；结果列表显示游戏、歌名、难度及备注摘要；支持查看原图、打开所在文件夹、编辑备注。

双击结果行打开图片查看器：可缩放浏览、按住左键框选一块区域，点「复制选区」或按 Ctrl+C 复制到系统剪贴板（不选则复制整图），便于把局部画面粘贴到聊天等位置；「复制整图」按钮一键复制整张图。图片内容只读，不做任何修改。
编辑歌名/难度/备注走检索页「编辑所选」按钮（作用于当前选中行）。
检索页在程序启动时即加载并显示全部索引记录（不再需要先操作筛选才刷新）。图片文件已被删/移走的记录标注「⚠ 文件缺失」；可用「清理失效记录」按钮二次确认后清除这些索引记录（只删记录，不动文件，图片内容始终只读）。

### 3.8 曲库管理

支持查看曲库更新时间、手动刷新、查看刷新结果。

> 现状（2026-10-17）：已实现「曲库信息」查看，以及曲库外置——各游戏歌名库合并为单文件放到程序同级的 config/SongLists/
> （Arcaea.json / maimai.json / chunithm.json，结构含 songs[{title, aliases}]，可直接编辑；缺失时回退内置曲库）。
> 应用内联网刷新已取消（用户决定不做，见 docs/04 阶段 10）。

### 3.9 备注功能

- 每张图一条自由文本备注，可随时补写、修改。
- 录入入口：校对弹窗、查询结果编辑。
- 备注存储于本地 SQLite，不写入图片文件，图片内容保持只读。
- 搜索结果列表显示备注前一部分，过长用省略号表示，点开查看全文。

### 3.10 识别算法实时优化

识别时若 OCR 只读出歌名的一部分（模糊、或被遮挡只露出部分文字），人工在确认弹窗补全歌名后，程序实时评估「这次人工输入是否值得学习」：

- 值得学：识别片段与最终歌名存在包含/相似关系（说明歌名部分可见，人工补齐的是残缺部分）→ 把该片段登记为最终歌名的别名，下次出现相同片段即可自动命中。
- 不值得学：OCR 完全没读到文本、或读到的内容与歌名差异过大（歌名被完全遮挡，人工是凭空录入）→ 不登记。

确认弹窗内实时显示评估结论（值得学习 / 不学习及原因）；学习记录可在检索页「学习记录」按钮查看与清空。学习记录外置于 config/LearnLogs/<game>.json，不写入图片文件。

评估按「片段」进行（整体文本与按空白切分的词逐一与歌名比对，取最贴合的一段）：只要有一段明显贴合歌名（前缀包含或相似度达标）即判定值得学习，并学习该片段。例如歌名区域同时读到歌名开头与曲师名（`Aeth void …`）时，会学习片段 `Aeth` 而非整串噪声。

同一套实时优化也适用于检索页「编辑所选」：打开某张已索引图片编辑歌名时，程序用该记录识别时读到的原始文本（index.db 的 observed_text 字段）与最终歌名做同样的评估，弹窗内实时提示、保存时登记学习别名——无需重新识别即可修正与沉淀。

### 3.11 曲名别名机制

Arcaea、舞萌、中二节奏统一采用别名机制；别名随曲库外置于 config/SongLists/<game>.json（每首曲目含 title 与 aliases）。

- 运行时：直接编辑 config/SongLists/<game>.json 增删别名，重启程序即生效。
- 开发/构建期：抓取与别名词源为 data/<game>_titles.json、data/<game>_aliases.json，经 scripts/build_library.py（或 scripts/build_alias_stubs.py + update_library_aliases.py）生成内置曲库，再由 scripts/export_song_lists.py 导出到 config/SongLists/。
- 算法实时优化学习到的别名另存于 config/LearnLogs/，匹配时一并计入。

## 4. 数据与文件组织

- 图片内容只读；整理时把 input 中的图片移动到 sorted。
- 运行时目录（程序同级）：input/（待处理原图）、sorted/（整理后图片）、config/（曲库、学习记录、图片索引）。
- 整理目录：sorted/<游戏>/<歌名>/<原文件名>。
- 待处理图片留在 input/，确认后才移动到 sorted。
- 曲库：config/SongLists/<game>.json（可编辑）；缺失时回退内置 library.db。
- 学习记录：config/LearnLogs/<game>.json。
- 图片索引：config/index.db（本地 SQLite）。

## 5. 非功能要求

- UI 简洁直观，中文界面。
- 稳定性与可回退：识别或整理出错可定位、可重试，不破坏原图。
- 可扩展：新增游戏时以配置/插件方式接入。
- 性能：批量导入不卡死界面，识别过程可后台运行并显示进度。

## 6. 用户已确认的关键决策

- 分发：Windows 绿色解压即用，暂不做 macOS。
- 整理方式：把 input 中的图片移动到 sorted（不再复制）。
- 歌名：保留日文/英文原文；中文译名作为搜索别名。
- 难度：只显示难度名称，不含等级数字。
- 弹窗选项：手动输入 / 跳过这张 / 标记待处理 / 暂时跳过以后添加；未录入的留在 input/ 待处理。
- 备注：每图一条自由文本，校对弹窗与结果页均可编辑，可按备注搜索，列表截断显示。
- 检索页双击：打开图片查看器并支持框选复制（编辑歌名改为检索页「编辑所选」按钮）。
- 算法实时优化：仅当人工输入对识别有价值（片段与歌名相关）时学习；完全遮挡时不学习，学习记录可查看/清空。
- 别名：三游戏统一 data/<game>_aliases.json，舞萌/中二别名先置空，后续再填。

## 7. 待验证风险

- 三款游戏曲库来源的可访问性与数据结构（阶段 0 优先验证）。
- 舞萌实拍照片时有时无的上屏内容对歌名定位的影响（以主结算画面稳定区域为准）。
- 上传图片可能经微信等渠道压缩或为新版 UI，样本数量少时分类特征需要持续校准。
