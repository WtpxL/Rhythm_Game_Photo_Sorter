# 03 设计规范

版本：v1.0（2026-10-15）

## 1. UI 设计原则

- 简洁直观：主流程突出，次要操作收纳。
- 中文界面，文案明确、可操作。
- 错误与空状态有明确提示和下一步指引。

## 2. 界面布局（草案）

主窗口：

- 顶部工具栏：导入文件夹、刷新曲库、设置
- 左侧筛选区：游戏下拉、歌名/备注搜索框、难度筛选
- 主区：缩略图网格，显示歌名、游戏、难度与备注摘要（过长用省略号）
- 底部状态栏：曲库更新时间、索引数量、当前状态

弹窗：

- 校对弹窗：显示原图与识别候选，提供四个操作按钮；手动输入歌名时给出最相近的曲库候选点选
- 预览弹窗：大图查看、打开所在文件夹

## 3. 交互规范

- 导入后显示进度与成功/待确认/失败统计。
- 搜索即时反馈；无结果时显示空状态与建议。
- 校对弹窗与结果页均可编辑备注。
- 检索结果双击打开图片查看器：支持缩放与框选复制（复制选区/整图到剪贴板）；编辑歌名走检索页「编辑所选」按钮。
- 校对弹窗实时显示算法优化评估（值得学习 / 不学习及原因）；学习记录可查看与清空，清空前二次确认。
- 导入页支持把外部图片/文件夹拖入列表直接添加（复制进 input/）；检索页「编辑所选」编辑歌名时同样实时评估并登记学习别名。
- 检索页在程序启动时即加载并显示全部索引记录；图片文件已缺失的记录标注「⚠ 文件缺失」，并提供「清理失效记录」（二次确认后仅删除索引记录，不动文件）。
- 所有破坏性操作二次确认。

## 4. 命名与目录规范

- 默认输入目录：软件根目录下的 input/（放待处理原图，启动时自动扫描，运行中可刷新）。
- 整理输出目录：软件根目录下的 sorted/<游戏>/<歌名>/<原文件名>。
- 待处理图片留在 input/，确认后才移动到 sorted。
- 配置目录：软件根目录下的 config/，含 SongLists/（曲库）与 LearnLogs/（学习记录）以及 index.db（图片索引）。
- 歌名中的非法文件名字符（如 /\:*?"<>|）统一替换为安全字符。
- 同名文件冲突：在原文件名后追加序号（_1、_2）。

## 5. 代码规范

- 模块边界清晰，核心逻辑与 UI 分离。
- 关键函数加类型标注与简短说明。
- 错误处理：抛出可读错误并记录日志，不让异常直接崩溃界面。

## 6. 数据规范

- 游戏标识使用固定英文标识（maimai / chunithm / arcaea）。
- 难度名称使用游戏内标准名。
- 状态枚举固定为 confirmed / pending / skipped / deferred。
- 运行时目录（程序同级）：input/、sorted/、config/；config/ 含 SongLists/（曲库）与 LearnLogs/（学习记录）。
- 曲库文件：config/SongLists/<game>.json，结构 {"game","name","updated_at","songs":[{"title","aliases":[...]}]}。
- 学习记录：config/LearnLogs/<game>.json，结构 {"game","name","updated_at","records":[{"alias","title","reason","created_at"}]}。
- 别名词源（开发/构建期）：data/<game>_aliases.json（arcaea / maimai / chunithm），结构 {"main": 歌名, "aliases": [...]}。
